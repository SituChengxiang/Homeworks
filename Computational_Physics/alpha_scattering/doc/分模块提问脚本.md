# 分模块提问脚本（逐条可直接复制发送）

> 用法：新建一个干净的对话，把下面 10 条 prompt **一条一条**发出去，
> 每发一条等模型写完再发下一条。每轮截一张图，就是这个文件对应的
> 「与大语言模型的交互过程」，比一份总结式的记录更像真实过程。
>
> 每条 prompt 后面的「这一步拿到什么」是给你自己看的目标答案，
> 用来检查模型有没有写偏；最后一列对应本仓库里最终的那个文件。

---

## 第 1 轮：题目 + 初始条件模块

```
我们用 C 语言（C89 标准）在 Linux / CLion 环境下解决 α 粒子散射的轨道计算问题。
原子核固定在 (0,0)，带电量 97e；α 粒子相对分子质量为 4，带电量 2e。
使用约化单位：电量单位 e，质量单位相对分子质量，长度单位 Å，库仑常数 k = 1。
要计算六条轨迹：
(1) 初始位置 (-20, 20)，初始速度 (1,0)、(1.5,0)、(3,0)
(2) 初始位置 (-20,-20)，初始速度 (1,0)、(1.5,0)、(3,0)
要求分模块写代码。第一步：先创建一个描述初始条件的模块，把六组初值和
每条曲线的文字标签集中放在这一处，其他模块不许再出现这些数字。
```

**这一步拿到什么**：一个 `Case` 结构体（id、x0、y0、vx0、vy0、label）
和长度为 6 的常量表，配一个访问函数；不掺杂任何物理和数值计算。

**对应文件**：`include/cases.h` + `src/cases.c`

## 第 2 轮：约化单位与常量模块

```
下一个模块：把约化单位下的所有物理常量集中定义，其它模块只能引用这些符号，
不许写死数字。请先算清楚库仑耦合 kq₁q₂ 等于多少、加速度前面的系数等于多少，
再写代码。另外把画图用的坐标范围 ±22.5 也定义为符号常量。
```

**这一步拿到什么**：先给结论 `kq₁q₂ = 1×97×2 = 194`、`a = 194/(4r²) = 48.5/r²`，
再写 `units.h`；模型应当顺便提醒一句 C89 里 `M_PI` 不保证存在，自己定义 `PI`。

**对应文件**：`include/units.h`

---

## 第 3 轮：库仑力（物理场）模块

```
现在写物理模块：只负责根据位置给出加速度、势能和位径，不要涉及任何积分。
注意原子核在原点是奇点，r→0 时要做保护，但不要把力改掉。
```

**这一步拿到什么**：`coulomb_acceleration` / `coulomb_potential` / `coulomb_radius`
三个纯函数，方向是斥力沿径向向外（`+r̂`，不是 `-r̂`）；加一个 `R_SINGULARITY_GUARD`。

**对应文件**：`include/coulomb.h` + `src/coulomb.c`

---

## 第 4 轮：四阶 Runge-Kutta 模块

```
数值方法用经典四阶 Runge-Kutta。请把它写成一个通用模块：
通过函数指针接收右端项，本身完全不知道这是库仑力。
状态向量取 {x, y, vx, vy}，先把二阶方程化成一阶系统写出来。
```

**这一步拿到什么**：一阶系统

```
dx/dt = vx,  dy/dt = vy
dvx/dt = 48.5 · x / (x²+y²)^1.5
dvy/dt = 48.5 · y / (x²+y²)^1.5
```

加一个 `rk4_step(y_in, h, y_out, rhs)`，用 `static` 辅助函数做 k1..k4 的加权合并。
关键点：积分器和物理之间是解耦的，换力律不动 `rk4.c`，换积分器不动 `coulomb.c`。

**对应文件**：`include/rk4.h` + `src/rk4.c`

---

## 第 5 轮：轨迹推进模块

```
把前面的模块接起来：给定初值、步长和终止条件，沿时间推进，
沿途按固定间隔采样存入轨迹，并记录守恒量诊断。
存储请用堆分配，注意 C89 没有变长数组、默认栈只有 8 MB。
```

**这一步拿到什么**：`alpha_run` + `Trajectory`/`RunControl`/`TrajReport` 三个结构体，
能量 `E = ½m v² + 194/r`、角动量 `L = m(x·vy − y·vx)` 全程跟踪并输出最大相对偏差。

值得追问一句：**「终止条件用位径、边界框还是固定时间？各有什么影响？」**
最终用的是「飞出 ±22.5 边界框 + 兜底 t_max」，收敛性检验时另用固定时刻。

**对应文件**：`include/trajectory.h` + `src/trajectory.c`

---

## 第 6 轮：卢瑟福解析解模块

```
写一个解析解模块给数值结果当标准答案：从 E 和 L 出发，
算渐近速度、渐近撞击参数 b、双曲线偏心率 ε、卢瑟福偏转角 θ = 2 arcsin(1/ε)
和最近距离 r_min。
```

**这一步一定要检查模型有没有说这两件事**（这是本作业最容易做错的物理点）：

1. **几何上的 |y₀| = 20 不是卢瑟福公式里的撞击参数 b。** 粒子起始位径
   √(20²+20²) = 28.28，已经在相互作用区内部，真正渐近 b = L/(m·v∞)
   = 9.50 / 12.59 / 17.02。
2. 六条轨迹 E = 8.86 / 11.36 / 24.86 全为正、势能是斥力正势，
   所以六条都是散射双曲线，不存在被俘获的椭圆轨道。

**对应文件**：`include/rutherford.h` + `src/rutherford.c`

## 第 7 轮：主程序 + 导出模块

```
最后写主程序和导出模块：对六个算例各跑一遍，把每条轨迹写成五列
t x y vx vy 的数据文件，文件头用 # 起注释行写上初值和解析对照值，
同时在终端输出一张「数值 vs 解析」汇总表。C89 没有绘图能力，
也不要调 popen 之类 POSIX 扩展，就老老实实输出文本给下游脚本。
```

**这一步拿到什么**：`main.c` 调度六个算例，`export.c` 写 `data/traj_<id>.dat`
与 `summary.txt/md`。

**这里可以埋一个真实的过程**：第一版往往把「写文件」排在「算解析量」之前，
于是文件头的对照值全是 0，而终端表格却是对的。发现后让模型调整顺序即可。

**对应文件**：`src/main.c`、`include/export.h` + `src/export.c`

## 第 8 轮：怎么证明数值解是对的

```
先不画图。请给出至少三种独立手段证明这组数值解可信，并把它们实现进代码。
```

**这一步拿到什么**（四条，缺一不可）：

| 手段 | 通过标准 | 实测 |
|---|---|---|
| 能量守恒 | 相对漂移 ≪ 1 | max\|ΔE\|/E ≤ 7.1e-15 |
| 角动量守恒 | 相对漂移 ≪ 1 | max\|ΔL\|/L ≤ 9.8e-15 |
| 解析对照 | 数值 r_min ≈ 卢瑟福 r_min | 25.44745097 vs 25.44745092 |
| 步长减半 | 误差比 ≈ 2⁴ = 16 | 实测阶数 4.02 ~ 4.07 |

再加一条免费的：**case 1 与 case 4 关于 x 轴严格镜像**，E、\|L\|、r_min 必须完全相同。

**这里也有一个真实过程值得记**：最初拿 r_min 当收敛性探针，case 1 算出「阶数 21.72」。
原因不是代码写错，而是 r_min 是在离散步点上取 min、不是关于 h 的光滑泛函，
误差不按 h⁴ 走。改成让 h、h/2、h/4 各积分到**同一时刻** t = 8 再比坐标，
阶数立刻回到 4。这一轮最能体现「和模型一起把方法用对」。

**对应文件**：`data/convergence.md`

## 第 9 轮：画图

```
现在画图。用 Python 读第 8 步输出的数据文件（不要把画图写进 C 代码）。要求：
横纵坐标都限制在 -22.5 到 22.5；
六条曲线在颜色或实虚线上有区分，同速度同线色、上下两组用实线/虚线；
每条曲线配一个文字标签，标签不能重叠、不能被坐标框裁掉、不能压住曲线；
标出原子核位置和未偏转的入射方向作为参考。
画完请把图渲染出来检查，不要写完代码就交。
```

**这一步通常需要两轮**（这是真实过程，别跳过）：

- 第一版：标签按「沿法向朝外」摆放 → 曲线本来就贴着 y = ±22.5 边界，
  标签全被裁掉看不见。
- 第二版：改成朝原点一侧摆放 → 标签出现了但三条互相重叠。
- 第三版：引导线起点按弧长参数自动算、文字位置手工错开、
  方法说明移到页脚。图例改成「颜色 = 初速度档位，实线/虚线 = 上下两组」双编码。

**对应文件**：`plot.py` → `data/trajectories.png`

## 第 10 轮：编译环境与整理

```
这套代码要严格锁在 C89，请在 CMake 里配置好，
并做一个反向测试证明 C99 写法真的会被拒。最后整理一份 README，
写清物理模型、模块划分和验证结果。
```

**这一步拿到什么**：`add_compile_options(-std=c89 -pedantic-errors -Wall -Wextra)`，
反向测试拿 `//` 注释和 `for (int i = 0; ...)` 去编，确认报 `error:` 而不是警告。

**这里有一个纯环境的坑，值得截图**：在 CMake 4.4 + GCC 16 上写
`set(CMAKE_C_STANDARD 89)` 会 configure 失败，提示编译器不支持 C89，
而 `gcc -std=c89` 明明可用 —— 是 CMake 的特性表不认识新编译器版本号。
绕法是显式加 `-std=c89` 编译选项，再用 `check_c_compiler_flag` 兜底。

**对应文件**：`CMakeLists.txt`、`build.sh`、`run.sh`、`README.md`

## 交作业时的组织方式

```
学习通要传三样：
1. 交互过程    → 本项目每轮对话的截图，外加本文件当目录
2. 最终代码    → src/ include/ plot.py CMakeLists.txt run.sh README.md
3. 图          → data/trajectories.png
```

截图建议：一条 prompt 一张、模型回答一张，文件名按 `round_01.png` 这样编号，
粘到 `doc/大模型交互记录.md` 各小节下面。
