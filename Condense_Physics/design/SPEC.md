# 设计规格与决策记录 · 对称性两页

这一轮把「反轴」和「四面体 24 个操作」当成一个前端工程重做。下面每条都是定下来的决定，
连同**为什么**——改主意时请连理由一起改，否则下一次又会退回旧写法。

## 1. 决策记录

| 决定 | 理由 |
| --- | --- |
| 拆成两个作业：`rotoinversion/`（反轴与等效点系）+ `tetrahedral-td/`（24 个操作） | 两件事的教学目标不同：一个讲"某种对称元素等价于什么"，一个讲"一个具体点群里有谁"。绑在一页里，投影时只能二选一显示。 |
| 共享层只有两个：`lib/`（纯数学）与 `design/`（呈现） | 晶胞那三页一行不改；新页之间该复用的确实只有矩阵内核和呈现规范。 |
| 主视图 = 左 3D + 右 2D 沿轴投影，**双视口联动** | 上一版只有 3D，"上下互为镜像"和"关于中心对称"要靠脑补深度——那恰恰是 3̄ 与 6̄ 的唯一区别。 |
| 2D 用 Canvas2D 符号层，不用 three.js 渲 | 半填圆点、虚线、上标是矢量符号；Canvas2D 画得最干净、代码最少、投影不糊，也不需要引入 SVG DOM 同步。 |
| 投影优先：**固定 16:9 舞台**，窗口比例不对就留黑边 | 老师投出去的画面必须就是设计时那张构图。 |
| 操作：**不留步进器件**，键盘/翻页笔驱动，图层与数据表收进抽屉 | 屏幕上出现一排"上一步/下一步"和数字点，学生的眼睛就去找按钮了。 |
| 交付仍是**离线单文件**，双击即开 | 课程验收形态，不变。Vite 构建后由 `design/vite-single-file.js` 把 JS/CSS 内联，产物零外部引用。 |
| 设计系统只服务这两页 | 三页已交过、正在被用；把它们一起改是另一件事，风险不该压在这次上。 |

## 2. 符号规范（2D 沿轴投影）

这是这一轮真正要评审的东西，`design/symbols2d.js` 就是它的实现，
`design/preview/symbol-preview.html` 是它的对照表。

| 符号 | 含义 |
| --- | --- |
| 半填圆点 | 填哪一半表示 z 的正负（z>0 填下半、z<0 填上半）；**同时把 z 的数值直接标在点旁** |
| 点旁的小指针 | 该点三面角 x 轴的投影方向；暖色 = 右手系，冷色 = 左手系（手性） |
| 穿过投影中心的虚线 | 两点关于对称中心 i 成对（"穿心"） |
| 同一位置上下叠成的一个圆 + 绿色双箭头 | 两点关于水平镜面 m⊥ 成对（"叠影"）——俯视时它们投到同一个 (x,y) |
| 中心 ⊕ / ⊖ | 群里有 i / 群里有 m⊥ |
| 一圈绿色椭圆 | m⊥ 这个镜面本身 |

### 2.1 第一次评审：只看俯视会骗人（已修正）

第一版只画教材俯视图，实测发现两处硬伤，是它自己把结论说反了：

1. **$ar{3}$ 的俯视图是一个标准的 6 次对称图案。** 数出来的方位角：上圈 120°/240°/360°、
   下圈 60°/180°/300°，六点每隔 60° 均匀排开 —— 长得就像它要否认的东西。
2. **$ar{6}$ 的"叠影"把点数合并掉了。** 6 个点投成 3 个位置，第一眼的读法是"这里只有 3 个点"，
   而结论恰恰是"有 6 个点，两两关于水平面成对"。图在数错的东西。
3. 更根本的一条：俯视能不能读出结论，取决于**先学会半填圆点这个约定**。论证被压在符号表上。

修正办法是加一种画法，而不是换掉教材画法：**上下圈展开图** —— 方位角原样保留，
高度换成半径（z 越大越靠外圈），于是 6 个点就是 6 个点，而"有没有水平镜面"变成一个数得出来的量：
**下圈有多少个点落在上圈的径向线上**。

```
      俯视                展开图（上圈/下圈）        对齐的下圈点数
1̄  2 点 → 2 处           1 / 1                       0   → 没有 m⊥
2̄  2 点 → 1 处           1 / 1                       1   → 上下互为镜像
3̄  6 点 → 6 处           3 / 3                       0   → 没有 m⊥，只有穿心的 i
4̄  4 点 → 4 处           2 / 2                       0   → 两者都没有
6̄  6 点 → 3 处           3 / 3                       3   → 全部对齐 → m⊥
```

这个数字由 `lib/projection.js` 算出，并且**当场自检**：若判定为 stack 却数出不全对齐，直接抛错。
$ar{3}$ 与 $ar{6}$ 的对比从此不依赖任何约定：一个是"下圈全落在径向线上"，一个是"一个都不落"。

于是 2D 视口的定稿是**两张一对**：展开图承担论证（它保证点数不被合并、结论可数），
教材俯视图承担对照（学生要能看懂书上的图和考卷上的画法）。半填圆点保留，
但每个点仍把 z 的数值直接标出来 —— 各家教材的半填朝向不完全一致，数字不会错。

**这套画法的赌注**：$\bar{3}$ 与 $\bar{6}$ 在 3D 里都是"6 个点"，但投影后
$\bar 3$ 落成 **6 处、3 对穿心**，$\bar 6$ 落成 **3 处、每处上下叠一对**，$\bar 4$ 落成 **4 处、两者皆无**。
学生不需要懂群论，也能看出"6̄ 里面没有 6 次"。预览页底部的五格结论就是这句话的表格版：

```
1̄  2 点 → 2 处   穿心 → i
2̄  2 点 → 1 处   叠影 → m⊥
3̄  6 点 → 6 处   穿心 → i
4̄  4 点 → 4 处   既不叠也不穿心
6̄  6 点 → 3 处   叠影 → m⊥
```

半填朝向各家教材画得不完全一致，所以**每个点都另标 z 的数值**：约定可以不同，数字不会。

## 3. 交互规范（投影场景）

| 键 | 作用 |
| --- | --- |
| `→` / `空格` | 下一步 / 继续播放 |
| `←` | 上一步 |
| `1 … 6` | 换反轴（作业 A） |
| `]` / `[` | 换操作（作业 B，按共轭类顺序） |
| `L` | 图层抽屉 |
| `D` | 数据表抽屉（幂次 / 坐标 / det / 置换） |
| `F` | 纯净全屏（只剩画面 + 字幕条） |
| `H` | 帮助 |

鼠标只做"点谁高亮谁"：3D 里的等效点、2D 里的半填圆点、数据表里的行，三向联动，
不依赖 hover，所有可交互元素有可见焦点态。

## 4. 目录与模块边界

```
lib/        matrix.js  3×3 正交矩阵、轴角分解、幂与闭包、动画路径
            rotoinversion.js  反轴群：6̄ = 3/m 这类结论从这里算出来
            tetrahedral.js    Td 的 24 个操作、顶点置换、Oh 的 48 个
            projection.js     数学 → 画法 的适配层（落成几处、几对穿心/叠影）
design/     tokens.css/.js    单位、色板语义、字号阶梯（全部由 --u 推，不写死像素）
            symbols2d.js      Canvas2D 符号层
            vite-single-file.js  单文件内联插件
            preview/          符号层对照页（设计系统的验收物）
rotoinversion/    src/{main.js, state/, ui/, render/, steps.js}  test/  build.sh
tetrahedral-td/   同上
```

边界规则：`lib/` 不认识 DOM 也不认识 three.js（node 里直接跑测试）；`design/` 不认识群论；
页面 `src/` 只做装配与状态。任何"结论"都必须来自 `lib/` 算出来的东西，不写死在文案里。
